GET /trainer/account — только собственный аккаунт, форма смены пароля.
POST /trainer/account/password — существующий auth handler и users.change:
текущий пароль, строгий allowlist полей, CSRF, обязательный точный Origin,
общий с /api/auth/password лимит, транзакционный аудит и отзыв всех сессий.
После сохранения — 303 /login, требуется новый вход. Ошибка формы — HTML 400
с пустыми полями пароля. Пароль, CSRF и SID не помещаются в localStorage.
POST /logout переиспользован без изменений. Восстановление — оператор ShumDev CLI.
Существующий sergei, его пароль и данные не менялись.

Каждая страница защищена requireAuth + requireRole(TRAINER). Весь namespace
/trainer и /api/trainer проверяется независимо; неизвестные вложенные маршруты
после проверки возвращают 404. /api/trainer/check сохранён. Новые CRM API,
export и attachments endpoints не создавались. OWNER и ADMIN получают 403.
Публичный /trainer.html остаётся отдельной страницей.

Идентичность только из req.user, загруженного существующим loadUser из сессии.
Query-параметры не используются для выбора аккаунта; body смены пароля строгий,
ID-поля отклоняются. Нет маршрута редактирования произвольного аккаунта.
Сервер передаёт шаблону только login/displayName/role и отдельный CSRF формы.
Шаблон экранирует пользовательские строки EJS. Cookie/store/CSP/no-store,
лимиты тела и публичные маршруты сохранены. Корень проекта не раздаётся.

Дополнительное укрепление существующего self password flow:
users.change проверяет expectedVersion внутри блокировки транзакции.
Если роль/доступ изменились после middleware, прежняя версия не позволит
сменить пароль даже при неизменном passwordHash. Это общий механизм для
OWNER/TRAINER/API. HTML /admin/account/password теперь явно требует OWNER,
/trainer/account/password — TRAINER; /api/auth/password остаётся для всех ролей.
AuthStore не менялся; UPDATE-only не воскрешает отозванные сессии.

Этап 11: согласовать и реализовать профиль User→TrainerProfile, клиентов,

следующем запросе. При отсутствии профиля — fail closed. Нельзя загружать
общий список и фильтровать его только в браузере. Внедряемый repository должен
пройти существующие и расширенные контрактные проверки trainer.js.
