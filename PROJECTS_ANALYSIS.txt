2. КАК РЕАЛЬНО УСТРОЕН IDEAL
Семь публичных HTML: index, about, trainers, trainer, shop, product, cart.
SCSS — семь страниц; готовые CSS — десять файлов, main.css общий для всех.
Десять JS: main.js — меню и preview-dialog; hero-motion.js — intro/параллакс;
sections.js — смена фона, карусель абонементов и purchase-dialog;
nutrition.js — непрерывный Coverflow, drag, клавиши, сведения выбранного примера;
about.js/trainers.js/trainer.js — reveal; shop.js — DOM-фильтрация и reveal;
demo-products.js — пять замороженных объектов; demo-cart.js — локальная корзина
и вывод product.html по единственному query id, без API.

Четыре components/*.html встроены в страницы; tools/sync_components.py
обновляет маркерные блоки семи страниц. Runtime fetch компонентов нет.
Порядок на главной: main → hero-motion → sections → demo-products → demo-cart
→ nutrition. На shop: main → demo-products → demo-cart → shop.
main.js использует глобальные функции/const и ожидает наличие общих элементов.
Это контракт текущих страниц, не самостоятельный модуль любой будущей панели.

Главная содержит статические расписание и прайс абонементов с оговорками;
это не TrainingSession, не остаток посещений и не механизм продажи.
О клубе — пять мест под фотографии; trainers — четыре ссылки на общий trainer.html.
shop — пять статических карточек с дублированием сведений справочника для no-JS.
product без JS не определяет query ID, честно показывает общий шаблон.
cart без JS не читает хранилище, сообщает об ограничении.
Корзина хранит только {id, quantity}, нормализует/объединяет строки, обрабатывает
ошибки хранилища, использует предел 99 и storage event. Память при запрете
хранилища ограничена страницей. Конкуренция вкладок: последняя запись побеждает.
Ни цены, ни заказы, ни персональные данные туда не пишутся.
Backend, БД, миграций, auth, приватной панели, SW/manifest, загрузок и ops нет.
Отсутствие защиты backend не является уязвимостью несуществующего backend.

Прочитаны ROADMAP, SHOP_NOTES, PRODUCT_CART_NOTES, TRAINERS_NOTES,
ABOUT_NOTES, CTA_NOTES, NEXT_STAGE. Старые заметки описывают прошлые этапы;
актуальный статус задают ROADMAP и документы этапа 7, не исторические обещания.

4. ПОДТВЕРЖДЁННЫЕ ОГРАНИЧЕНИЯ / НЕ ВЫДУМАННЫЕ УЯЗВИМОСТИ
— nutrition.js: syncInfo читает IdealProducts[active], а карточки берёт из DOM.
  Перестановка только одной коллекции рассогласует описание и изображение.
  При реальном каталоге связывать по ID; сейчас порядок согласован визуально
  по исходным данным, браузерная работа здесь не проверялась.
— demo-cart.js: read/persist запускаются при загрузке; state вкладок разрешается
  через storage event без транзакций. Это демо, не механизм серверного резерва.
  normalize обрабатывает не более 500 входных строк; это техническая защита,
  не бизнес-лимит заказа. Нельзя переносить её в учёт склада.
— demo-products.js, shop.html и подписи index.html: несколько мест одного контента.
  Пока нужны для Go Live/no-JS; при серверном рендеринге один источник.

  Не подключать вслепую на будущую страницу входа без этих элементов.
— index.html: inline script hero-intro в head; JS устанавливает style-свойства
  в hero-motion.js/sections.js/nutrition.js. Будущий CSP проверить на этих
  механизмах, вынести inline script или применить nonce/hash. Наличие inline
  само по себе не доказательство XSS. Не включать unsafe-inline для scripts

— main.scss: остались неиспользуемые .nutrition-dialog; ранее это отмечено

  исправляет число после запуска. Без JS подпись неточна. Зафиксировано,
  frontend не исправлялся в документационном патче.
