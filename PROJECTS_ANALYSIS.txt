7. ПОДТВЕРЖДЁННЫЕ ОГРАНИЧЕНИЯ И УСЛОВИЯ ПРОЯВЛЕНИЯ
Это наблюдения по коду, не утверждение об эксплуатации уязвимостей.
— Содружество server.js/control.js: часть модулей выключена только для страниц,
  но API подключены. Не использовать ENABLED_ROUTES как разграничение прав.
— Содружество push.service.js/server.js: select → send → update без claim;
  два цикла или остановка после send до update допускают повтор. Один удачный
  device помечает всё напоминание: неуспешные устройства не повторяются отдельно.
  sendToOwner не перепроверяет active; персональный цикл тоже не фильтрует owner.active.
— Транспортные public-orders.routes.js/push.service.js: после commit нет job;
  остановка процесса теряет отправку, временные ошибки не получают durable retry.
— Содружество settings.routes.js: subscribe upsert меняет ownerId существующего
  endpoint; нет conflict-проверки другого аккаунта, как у транспортных CRM.
  Endpoint проверяется как текст, без allowlist провайдеров.
— Содружество prisma-session-store.js/create-owner.js: отзыв по JSON contains
  строки id, а не FK userId; возможны избыточные совпадения префиксов ID.
  Это не готовый точный механизм отзыва всех сессий IDEAL.
— Содружество require-csrf.js: сравнивается длина JS-строк перед timingSafeEqual
  Buffer; равная длина строк не гарантирует равную длину байтов. Некорректный
  Unicode-заголовок может дать ошибку вместо контролируемого 403. Код транспорта
  safeEqual сравнивает длины Buffer — более подходящий образец.
— Транспортные scripts/create-owner.js: пароль readline вводится с обычным
  echo; повторный upsert меняет пароль/роль, но не отзывает Session. IDEAL нужен
  скрытый ввод, явный reset и атомарный отзыв. Logout auth.routes.js подавляет
  ошибку удаления Session: очистка cookie сама по себе не доказывает серверный отзыв.
— Все три: вход не требует pre-login CSRF token, использует Origin-механизм;
  IDEAL предложен более строгий протокол login token+Origin. Это различие
  требований, не заявление о доказанном обходе браузерной защиты.
— Транспортные control.routes.js/server.js: OWNER-only бизнес-API при enum STAFF
  и auth-only HTML. Готовой матрицы тренера/оператора здесь нет.
— Транспортные uploads.routes.js: проверка начала файла без decode/pixel limit,

— Транспортные backup-database.js: copyFile без остановки/backup API, WAL и

— Содружество audit.service.js и транспортные routes/carriers.control.routes.js + lib/activity.js:
