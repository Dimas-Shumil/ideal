БЕЗОПАСНОСТЬ И КОНТРАКТ
Панель и /api/admin/* независимо ограничены действующим OWNER.
Гостю API отвечает 401, страницы ведут на /login. ADMIN/TRAINER получают 403.
requireAuth использует originalUrl: смонтированный Express router не должен
превращать API 401 в redirect из-за обрезанного req.path.

GET /api/admin/employees?q=&role=&active=&page= отдаёт только DTO
id/login/displayName/role/active; total и фильтры. По 25 записей.
POST /api/admin/employees: login,displayName,role,password.
POST /api/admin/employees/:id/name: displayName.
POST /api/admin/employees/:id/role: role.
POST /api/admin/employees/:id/active: active, строка "true" либо "false".
Для каждого POST сотрудника обязательны ownerPassword и confirm="yes",
а также CSRF (_csrf либо x-csrf-token) и точный Origin.
HTML-формы используют те же пути без /api. Произвольного PATCH нет.
Неизвестные поля запрещены, роль/ID актора не берутся из тела.
JSON boolean в active намеренно не поддерживается: контракт совпадает с формой.
Пароль OWNER проверяется при КАЖДОМ изменении сотрудника и при создании,
что строже минимального требования только для привилегированных прав.
Ошибочные попытки ограничены rate limit; все изменения сотрудника — не более
30 запросов за 15 минут на владельца, плюс прежний общий лимит.

Сервис users остаётся единым для CLI и HTTP. Его блокировка advisory lock
сериализует проверку последнего OWNER, проверку актора, запись, аудит и отзыв.
HTTP дополнительно передаёт ожидаемый authVersion актора; конкурентный отзыв
прав после middleware не допускает сохранение через устаревший контекст.
Имя сохраняется с аудитом без увеличения authVersion/отзыва сессий.
Изменение роли/active увеличивает authVersion и удаляет сессии точно по userId.
Даже повторное сохранение той же роли/активности отзывает сессии — это явно
указано в формах. Дубликат логина проверяется под той же блокировкой.
Провал записи AuditEvent откатывает изменение; пароли в аудит не попадают.
Прежний UPDATE-only store не изменён, отозванная сессия не создаётся заново.

POST /admin/account/password переиспользует существующую смену пароля:
currentPassword,newPassword,_csrf. Проверка текущего пароля, прежний лимит,
CSRF/Origin, отзыв всех сессий, destroy cookie и 303 /login.
Ошибка HTML-формы показывается в панели без повторного вывода паролей.
Прежний /api/auth/password и контракт TRAINER сохранены.

ИНТЕРФЕЙС
Все действия доступны без JS: обычные ссылки/GET/POST, серверная валидация,
явная отметка подтверждения и пароль в каждой критичной форме.
JS добавляет блокировку повторной отправки, сообщение сохранения, фокус ошибки
и восстановление кнопок при возврате из истории. Модальных диалогов в панели
нет, поэтому фокус не запирается; Escape не отменяет уже отправленный POST.
Формы изменения вынесены на отдельную страницу с текущим именем/ролью/статусом.
Нативные required/minlength/maxlength дополняются строгой серверной схемой.
Ошибка инфраструктуры использует прежнюю безопасную страницу с requestId.
Стили BEM в owner.scss, готовый owner.css включён; нет CSS variables/:root,
!important, React и тонких стрелок. Светлый текст кнопок, focus-visible,
active scale(.98), reduced motion. Для ручной сборки после правок:
node node_modules/sass/sass.js --no-source-map site/sass/owner.scss site/css/owner.css
