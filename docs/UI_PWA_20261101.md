## Windows CMD — применение

Открой CMD в текущей папке IDEAL (там, где package.json) и сначала проверь:

```bat
git status --short --branch
git branch --show-current
git remote -v
git log -1 --oneline
```

Ожидаемая ветка main. Сверь адреса origin/upstream с PabloAlligator/ideal
и Dimas-Shumil/ideal: на разных компьютерах они могут быть назначены по-разному.
Если есть свои незакоммиченные изменения в перечисленных файлах, сначала сохрани
их копии/коммит; не перекрывай их вслепую.

Распакуй ZIP в отдельную временную папку. Скопируй из неё site, tests и docs
в корень текущего проекта с объединением папок и заменой файлов. .env не менять.
Если архив лежит в стандартной папке Downloads, вместо копирования можно выполнить
из корня проекта (замени путь, если браузер сохранил файл в другом месте):

```bat

git diff --stat
git diff --check
node --check site/scripts/pwa-install.js
node --test tests/pwa-install.test.js tests/push-sw.test.js tests/static-site-and-photos.test.js tests/schedule-dates.test.js tests/crm-dates.test.js
```

Ожидаемо 25/25 выбранных тестов. Они не подключаются к PostgreSQL и не требуют
зависимостей проекта. Пересборка CSS, npm ci и команды Prisma для патча не нужны.
Запусти настроенный проект обычной командой:

```bat

```

Если сервер уже запущен, оставь его работающим: изменения — статические CSS/JS.
Открой сайт, нажми Ctrl+F5 и проверь:

## Windows CMD — commit и push

После проверки повторно проверь ветку, remote и весь staged diff:

```bat
git branch --show-current
git remote -v
git status --short --branch
git add --pathspec-from-file=docs/UI_PWA_PATCH_FILES.txt
git diff --cached --stat
git diff --cached --check
git diff --cached
```

В индексе должны быть только нужные изменения. Если до начала работы уже были
другие staged-файлы, разберись с ними до коммита. На main и при правильном origin:

```bat
git commit -m "fix: floating trainer photos and PWA install banner"
git push origin main
git status --short --branch
```

Push выполняется в адрес origin из git remote -v. Если изменения также нужны
во втором репозитории, синхронизируй его по принятому для проекта порядку после
проверки обоих remote; force push не использовать.

## Production — статическое обновление

Сначала отправь коммит в тот репозиторий, который сервер будет подтягивать.
На сервере:

```sh
cd /var/www/ideal
git status --short --branch
git branch --show-current
git remote -v
```

Далее — только при чистом рабочем дереве и ветке main. Выбери remote, в котором
уже есть этот коммит. Для origin:

```sh
git fetch origin
git log -5 --oneline origin/main
git diff --stat HEAD..origin/main
```

Убедись, что среди входящих изменений есть этот патч. Если там есть другие
изменения, оцени их отдельно: приведённые инструкции относятся к этому
статическому патчу. Затем:

```sh
git merge --ff-only origin/main
git status --short --branch
curl -fsS https://ideal-abakan.ru/health/live
curl -fsS https://ideal-abakan.ru/health/ready
```

Если на сервере используется upstream, замени origin на upstream во всех
четырёх командах fetch/log/diff/merge. При конфликте/невозможности fast-forward
остановись и посмотри статус — reset/clean/force не нужны.

Для данного патча не нужны перезапуск PM2, npm ci, prisma migrate, db push,
удаление кэшей, сброс Push или изменение .env. Обнови браузер через Ctrl+F5.
