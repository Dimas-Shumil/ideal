# ИДЕАЛ — отдельное PWA для сотрудников (01.11.2026)

## Назначение
- Публичное PWA сохранено (`/manifest.webmanifest`, прежний id `/employee-app`, `/`).
- Для внутренних страниц и страницы входа используется `/staff-manifest.webmanifest` с новым id `/ideal-staff-app` и точкой запуска `/workspace`.
- `/workspace`: без сессии → `/login`; OWNER → `/admin`; ADMIN → `/crm/clients`; TRAINER → `/trainer`. Прямой URL не предоставляет прав.
- Установка: войти → в меню «Приложение» (`/application`) нажать «Установить рабочее приложение» (если браузер предлагает) либо выполнить установку через меню браузера. iOS Safari: «Поделиться» → «На экран Домой».
- Установка отдельного приложения зависит от поддержки браузером отдельных manifest id; iOS может хранить cookies отдельно от Safari. После первой установки возможен однократный вход.
- Оба приложения используют прежний `/push-sw.js` с `scope: /` и тот же офлайн-экран: личные данные, HTML кабинетов, CSRF, API не кэшируются. Push только по отдельному согласию, существующие подписки и worker не удаляются.

## Сессия и защита
- Стандартный вход **без галочки** — старые `SESSION_IDLE_HOURS` (8 ч по умолчанию) и `SESSION_ABSOLUTE_DAYS` (7 дней).
- На доверенном личном устройстве сотрудник может отметить «Оставаться в системе на этом личном устройстве»; cookie HttpOnly + Secure (production) + SameSite=Lax и PostgreSQL-сессия действуют **не более 30 календарных дней**, с окончательным пределом на стороне БД. После 30 дней нужно повторить вход. Нет бессрочных токенов или хранения паролей в браузере.
- `SESSION_TRUSTED_DAYS=30` — необязательный параметр, допустимо 7–30 дней; по умолчанию 30. `.env` не изменяется автоматически.
- Явный выход, смена пароля, деактивация сотрудника и отзыв доступа должны продолжать закрывать доступ. На общем устройстве галочку не выбирать.
- Нельзя гарантировать сохранение сессии при очистке cookies/данных сайта, сбросе настроек браузера, изменении SESSION_SECRET или удалении аккаунта.

## Проверка перед production
1. `node --check` для JS; unit-тесты и `npm test` только на тестовой БД.
2. Чистый браузер Chrome Android / Edge Windows: открыть `/login`, войти с галочкой, `/application`, установить приложение; после закрытия и повторного запуска убедиться в прямом входе в нужный рабочий раздел.
3. Проверить остальные роли, переходы по меню, Push, выход и отсутствие приватного контента в Cache Storage. На iPhone проверить Safari → на экран Домой.
4. Без галочки — старый режим входа и срока жизни сессии. Проверить `Set-Cookie` с `Expires/Max-Age` и дату `AuthSession.absoluteAt` на **тестовой БД**, не публиковать их.
5. Для сервера достаточно `git pull`/fast-forward и `pm2 restart ideal`; миграций, новых npm-зависимостей и изменения production `.env` не требуется.
