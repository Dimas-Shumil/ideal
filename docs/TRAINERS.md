# Публичные тренеры — этап 18

Сценарий согласован пользователем 25 октября 2026: все восемь пунктов предложения
приняты. Только просмотр, без регистрации, кабинета клиента, онлайн-записи и заявок.

## Источник и публикация

Используется существующий TrainerProfile с обязательной уникальной связью userId.
Профилей без учётной записи, перепривязки и публичных OWNER/ADMIN нет. Само создание
сотрудника или внутреннего TrainerProfile не публикует его. OWNER → Публичные тренеры
видит сотрудников TRAINER и сохранённые профили сотрудников с изменившейся ролью.
«Подготовить скрытый профиль» создаёт его только для активного TRAINER; если профиль
уже существует, открывает существующий без сброса имени и версии.

Редактирование, загрузка/замена/удаление фотографии, порядок и публикация доступны
только OWNER. ADMIN/TRAINER не получают эти страницы/операции. Все формы работают
без JS. Поля сохраняются отдельно от явной публикации с подтверждением материалов.
Сохранение скрытого профиля не публикует его. У опубликованного правки видны после
обновления страницы. Порядок: publicOrder по возрастанию, затем publicName и publicKey.

Публичный показ требует publicVisible=true, непустого publicName и активного TRAINER.
Отсутствие имени скрывает каталог/профиль/фото, в расписании остаётся занятие без имени.
При возвращении имени ранее включённый флаг публикации продолжает действовать.
Деактивация или смена роли TRAINER снимает флаг профиля и повышает publicVersion;
материалы сохраняются. Возврат в активный TRAINER сам профиль не публикует.
Занятия сохраняют прежние флаги: расписание ведёт себя как в этапе 17.

## Поля и публичное имя

| Поле | Лимит символов |
| --- | ---: |
| publicName — единственное публичное имя | 100 |
| specialty — специализация | 300 |
| summary — краткое описание | 1000 |
| biography — биография | 5000 |
| experience — стаж текстом | 500 |
| qualification — образование/квалификация | 3000 |
| approach — подход | 3000 |
| directions — направления работы | 2000 |
| achievements — достижения | 3000 |

Обычный текст, обрезка внешних пробелов, экранирование EJS, HTML не исполняется.
Обязательное условие публикации — только имя. Остальные материалы не выдумываются:
пустые подробные блоки не выводятся, в карточке без специализации честное пояснение.
Цен/условий персональных тренировок и демонстрационного блока записи в профиле нет.
Существующие общие кнопки записи остаются поясняющими заглушками, не отправляют формы.

User.displayName остаётся внутренним именем; копирования/fallback нет. publicName
и publicVersion общие с расписанием: изменение с одной страницы делает старую форму
другой устаревшей (409), включая формы фотографии и публикации. Кнопки сохранения
не меняют логин, роль, пароль или права сотрудника.

## Фотографии и backup

Одна фотография в отдельной TrainerPhoto, BYTEA PostgreSQL; связь с TrainerProfile,
без сохранения пользовательского имени файла или внешнего URL. При отсутствии —
существующий /site/img/trainer-placeholder.svg. Карточка сохраняет прежний монохромный
стиль. Пропорции изображения адаптируются существующей вёрсткой; исходник хранить
у клуба отдельно, приложение хранит только нормализованный WebP.

Один статический JPEG/PNG/WebP до 5 МиБ, до 20 млн пикселей. Multipart до 6 МиБ,
ограничения частей/полей, неизвестные/повторные поля отклоняются. Проверяются MIME,
сигнатура и декодирование Sharp; анимация, SVG, повреждённые и чрезмерные изображения
отклоняются. Коррекция EXIF-ориентации, удаление метаданных, WebP quality 82,
вписывание в 1600×1600 без увеличения, результат не более 1 МиБ.
Используется существующая обработка магазина без изменения его поведения.

Origin проверяется перед чтением upload, роль — до парсера, CSRF — перед обработкой
изображения/записью. Изменение фото/версии/аудит/ключ операции коммитятся атомарно.
Повтор формы использует digest нормализованного изображения; устаревшая версия — 409.
Публичное фото доступно только при доступном публичном профиле и возвращает no-store.
OWNER видит сохранённое фото скрытого профиля через отдельный закрытый маршрут.

Фото входят в обычный pg_dump всей БД. Для резервирования не нужна папка uploads.
Перед миграцией нужен новый backup вне проекта, его проверка pg_restore --list;
проверка восстановления выполняется отдельно в отдельной БД. Digest-снимок не backup.
После начала загрузок включать новую таблицу в дальнейшее полное резервирование.

## URL, ошибки и расписание

/trainers.html — каталог; /trainers/<publicKey> — профиль. publicKey — 32 случайных
hex-символа от отдельного UUID, не userId/profileId/логин; неизменен при переименовании.
/trainer.html возвращает 301 в каталог, поскольку старый шаблон был общим.
Статические HTML для Go Live показывают сообщение о необходимости Node/Express,
не содержат самостоятельного демонстрационного каталога/биографий.

Пустой каталог: 200 и «Профили тренеров пока не опубликованы». Скрытый, безымянный,
недоступный сотрудник, неизвестный ключ: одинаковый 404 профиля/фото. Ошибка БД: 503,
честное сообщение, без внутренней ошибки или подмены пустым каталогом.
Параметры query каталога и профиля не поддерживаются: HTTP 400 при передаче.
Публичный JSON API отсутствует, публичных мутаций нет. На профиле обычная ссылка
«Смотреть расписание» → /schedule.html. Нет фильтра по тренеру, копии расписания,
показа персональных занятий, вместимости, записей и участников.

## Граница данных и безопасность

Публичный модуль использует отдельные allowlist select и явные DTO. Каталог:
name, url, photoUrl, hasPhoto, specialty. Профиль дополнительно содержит только
summary/biography/experience/qualification/approach/directions/achievements.
Проверка роли/активности в where, без выбора полного User. Служебный trainerId из
photo relation остаётся внутри преобразования, в DTO не включён. Нет клиентов,
назначений, внутренних UUID, логинов, паролей, ролей, authVersion, версий и истории.
Фото выбирается отдельным запросом, каталог не читает бинарные данные.

Мутации используют session/authVersion, CSRF/Origin, rate limit, accessLock,
повторную проверку OWNER и живой сессии внутри транзакции, publicVersion,
идемпотентный ключ CrmOperation/fingerprint и AuditEvent. Сбой аудита откатывает всё.
Архитектура Argon2id, сессий и права остальных модулей не меняются.
Каталог/профиль/фото no-store, noindex, без гостевой сессии, вне sitemap и offline-кэша.
PWA/SW allowlist, manifest и Push не меняются. Общие публичные partials продолжают
синхронизироваться tools/sync_components.py, меню кабинетов — только panel-nav.ejs.

## Локальная приёмка

Применение и сравнение прежних данных — DEVELOPMENT.md, этап 18.

- Пустой каталог; подготовка скрытого профиля; сохранение без публикации; имя обязательно.
- Публикация/порядок/снятие; прямые ссылки, неизвестный ключ, старый trainer.html.
- Имя меняется одинаково в профиле и расписании; устаревшие формы обеих страниц дают 409.
- Деактивация/смена роли скрывают профиль и фото; материалы остаются; возврат требует
  новой публикации профиля; явно опубликованные занятия сохраняют старое поведение.
- Фото: отсутствие, upload, замена, удаление, лимиты/повреждённый файл/анимация/SVG;
  без доступа у ADMIN/TRAINER/гостя, без частичных изменений после ошибки.
- Desktop/mobile, длинные имена, клавиатура/focus, reduced motion, JS выключен,
  меню, переходы к профилям/расписанию, отсутствие ошибок JS и горизонтального overflow.
- Главная: hero, Coverflow, drag/клавиатура, смена фона, карусели; остальные модули
  — полный npm test. Реальные телефоны/Safari/Push отдельно, без подмены эмуляцией.
