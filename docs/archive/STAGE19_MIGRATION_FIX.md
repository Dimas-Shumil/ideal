# Исправление неудачной тестовой миграции этапа 19

Пользователь сообщил об ошибке на migrate deploy отдельной ideal_auth_test до запуска
тестов. В CHECK ContentEntry_key_check ошибочно присутствовал gen_random_uuid(),
что смешивало UUID с текстовыми ключами. Это ошибка ZIP-патча. Исправлен только
новый, ещё не применённый успешно файл 20261025170000_public_content/migration.sql.
В CHECK теперь только шесть строковых ключей; генерация UUID остаётся в default
публичного ключа фото и в шести строках INSERT. Прежние восемь миграций неизменны.

Остановить приложение, распаковать ZIP исправления в корень IDEAL с заменой.
В CMD выполнить по одной команде, продолжать только после кода 0:

```bat
node tools/stage19-resolve-test.mjs
npm test
```

Инструмент не использует dev как fallback. Проверяет TEST_DATABASE_URL, суффикс
*_test, отличие БД и пользователя от dev, затем read-only проверяет отсутствие
ContentEntry/ContentPhoto и успешно завершённой миграции. Только после этого
вызывает prisma migrate resolve --rolled-back для неудачной попытки в TEST_DATABASE_URL.
Это исправление служебного статуса, не удаление таблиц и не откат данных.
При наличии новых таблиц или успешной миграции инструмент останавливается.
Не выполнять migrate reset/db push, не удалять записи _prisma_migrations вручную.

Ожидается полный npm test 216/216. Полный новый прогон PostgreSQL пока не подтверждён.
До успешного полного теста не применять миграцию к ideal_dev. Dev в сообщении
пользователя не затрагивалась; её сохранность не подменяется этим выводом.
