# Этап 16 — интеграция, SEO и приёмка

Дата: 25 октября 2026. Основа — переданный ZIP после `8f5bd7f`.
Изменения согласованы пользователем: связать абонементы на главной с CRM,
добавить OWNER-публикацию/порядок, подготовить SEO без выбранного домена.
Локальная приёмка пользователя и Git-коммит этого патча ещё не выполнялись.

## Изменения

- В MembershipPlan добавлены publicVisible=false, publicOrder=0 и CHECK 0–10000.
- Форма OWNER /crm/plans/:id работает без JS; прежние проверки доступа/версии,
  CSRF/Origin и аудит сохранены. ADMIN/TRAINER новых прав не получили.
- Главная через Express показывает опубликованные активные тарифы CRM, цену и
  условия за человека. Данные выбираются по allowlist публичных полей.
- Снимки проданных абонементов не меняются; поля публикации не попадают в новые снимки.
- Пустые категории/списки не заменяются выдуманными ценами. Обе категории читаются
  без JS, при JS сохранены переключение, карусель, клавиатура и drag.
- Go Live вместо статического прайса объясняет необходимость Express.
- Онлайн-продажи абонементов нет; кнопка открывает «Условия оформления».
- SEO_ORIGIN/SEO_INDEXABLE необязательны. Без выбранного домена индексация закрыта,
  robots.txt запрещает обход, sitemap.xml пустой, localhost не подставляется.
- При явном включении в production индексируются главная, каталог и активные товары.
  Canonical, title/description, OG и минимальный WebSite JSON-LD; новый hash в CSP.
- Демо/незаполненные страницы, фильтры, сессии, кабинеты и API остаются noindex.
- /index.html → 301 /, query сохраняется; внутренние ссылки ведут сразу на `/`.
- Добавлен read-only инструмент снимков/сравнения прежних данных для локальной миграции.
- Обновлены текущие документы; старые миграции, package.json/lock, .env и приватные
  файлы не менялись. Зависимости не обновлялись. Удалений файлов нет.

## Сохранность при миграции

На отдельной ideal_preserve2_test сначала применены прежние пять миграций,
затем внесены синтетические строки в User, Client, MembershipPlan,
MembershipPurchase, Membership и AuditEvent. Применена только новая миграция.
Сравнены количества строк и digest прежних полей всех **24 таблиц**:
совпадают. Новые поля старого тарифа: publicVisible=false, publicOrder=0.
Повторный migrate deploy не нашёл ожидающих миграций.

Дополнительно проверен snapshot-режим поставляемого stage16-db-check.mjs
до и после миграции: результаты совпали. Compare-режим отдельно проверен на
синтетических JSON: одинаковые метаданные принимаются, изменённые отклоняются. Сравнение исключает _prisma_migrations
и только два новых поля MembershipPlan. Это проверка подготовленных тестовых данных,
не резервная копия и не доказательство сохранности рабочей БД пользователя.
Для рабочей БД даны отдельные команды в DEVELOPMENT.md.

## Что остаётся неподтверждённым

Домен/реальная индексация, TLS/Nginx, локальный полный прогон Windows после патча,
реальные фотографии/биографии/контакты/реквизиты и юридические тексты.
Реальная установка PWA на телефоны и Safari, доставка системного Push и жизненный
цикл обновления SW на реальных устройствах заново не проверялись.

Публичное расписание, онлайн-запись, заявки, клиентская регистрация и онлайн-оплата
абонементов не добавлялись. Не заявляется полная готовность к production.
