# Удаление ошибочных записей и единое меню кабинетов

24 октября 2026 года. Дополнение к этапу 13. Без перехода к магазину/PWA.

## Поведение

OWNER может физически удалить отменённую запись клиента без посещений либо отдельное
отменённое занятие с его отменёнными записями, если нет посещений. REVERSED также
блокирует удаление. В форме обязательны причина и checkbox подтверждения; проверяются
версия, server session/authVersion, CSRF/Origin, роль и UUID replay key.
ADMIN/TRAINER удалять не могут. Удаление без посещений не меняет деньги/абонементы.
Клиенты сохраняются. Удаление занятия не затрагивает другие экземпляры серии.
Сначала выполняется штатная отмена со своими Push; удаление повторных Push не создаёт.

Журналы не удаляются: CrmEvent/AuditEvent сохраняются, ScheduleEvent получает
lessonId=NULL с прежним ID в details.deletedLessonId. Новый LESSON_DELETED хранит
снимок параметров, BOOKING_DELETED — запись клиентской истории. Всё в одной транзакции
под общим accessLock. Ошибка аудита откатывает физическое удаление. Повтор POST не
создаёт повторного удаления/аудита, а другой lessonId с тем же booking replay key
не проходит fingerprint. Миграции и изменения схемы не требуются.

Навигация вынесена в server/views/partials/panel-nav.ejs для owner/trainer/CRM/schedule.
Порядок больше не меняется при переходе между разделами. Подсветка вычисляется по
res.locals.currentPath. Права backend не расширены.

## Применение

Распаковать ZIP поверх IDEAL с заменой, выполнить npm test, затем перезапустить
npm run dev и обновить страницу Ctrl+F5. npm ci и новые миграции для этого дополнения
не требуются. Удаляемых файлов нет. Git commit/push — после локальной приёмки.
