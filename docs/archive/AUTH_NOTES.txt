TRAINER: только назначенные клиенты/свои занятия по AUTH_PLAN и политикам.
Вход по уникальному логину; email и SMTP не нужны.
Восстановление — оператор ShumDev через CLI, со скрытым вводом и отзывом
сессий. Тренер/администратор обращается к владельцу, владелец — к ShumDev.
Idle 8 часов, absolute 7 суток. Анонимная сессия входа — 15 минут.

2. ЧТО ДОБАВЛЕНО
Express 5 / ESM; app.js отдельно от index.js. БД через PostgreSQL / Prisma 7.
Ровно User, AuthSession, AuditEvent + служебная _prisma_migrations.
User.role — enum, без множественных ролей, без профилей/клиентов/CRM.
express-session — единственный механизм сессий. AuthStore расширяет
connect-pg-simple: наследует destroy/cleanup/close, адаптирует get/set/touch
и отдельное установление аутентифицированной сессии. Таблицу создаёт только
Prisma migration, createTableIfMissing=false. Явные userId FK/index/authVersion.
GET сессии фильтрует серверные idle/absolute и актуальную активность/версию.
После входа regenerate SID и CSRF. Сессия связывается с актуальной версией
пользователя под общей advisory transaction lock. Изменения доступа используют
ту же блокировку; роль и active повторно читаются сервером на запросе.
Authenticated set — UPDATE-only: снимок параллельного запроса не может
воскресить удалённую logout/reset сессию. Touch не вставляет строки и не
продлевает absoluteAt. Анонимный set не может заменить привязанную сессию.
Пароль/роль/active меняются транзакционно с audit, increment authVersion
и DELETE сессий по точному userId. Защита последнего активного OWNER под
общей блокировкой, включая конкурирующие операции. Прямой ручной SQL
в обход сервисов не является поддерживаемым способом управления аккаунтами.

Argon2id: memory 65536 KiB, timeCost 3, parallelism 1. На процесс максимум
две одновременные операции хеширования/проверки, иначе безопасный 503.
Новые пароли: 12–128 символов (JS UTF-16), максимум 256 UTF-8 байт, без NUL.
Не обрезаются и не нормализуются. Перед production измерить latency на VPS.
Неизвестный аккаунт проверяет случайный dummy hash, без seed-пароля.
Логины: 3–64 ASCII-символа a-z/0-9/._-, первый — буква/цифра;
пробелы по краям убираются, регистр приводится к нижнему. Уникальность в БД.

CSRF session token + обязательный точный Origin для login/logout/password.
Referrer-Policy strict-origin-when-cross-origin сохраняет Origin у no-JS форм.
Отсутствующий Origin отклоняется; Referer не заменяет проверку. Без CORS.
Вход form-urlencoded работает без JS. returnTo не принимается: перенаправление
только на фиксированный адрес роли. Ошибки входа общие; password не отражается.
Cookie HttpOnly, SameSite=Lax, Path=/, без Domain; production Secure и
__Host-ideal.sid. Development имя включает PORT (отдельно от других проектов).
Cookie может продлеваться rolling, но серверный absoluteAt никогда не растёт.
Закрытые/auth/API ответы и ошибки — Cache-Control no-store.

Общие HTTP лимиты: 300 запросов/IP/минуту. GET login 60/IP/15 минут;
POST login 30/IP и 10/нормализованный логин/15 минут, успешные запросы
вычитаются из auth-счётчиков. Ключ логина — HMAC, не открытый логин в store.
Смена пароля 5/пользователь/15 минут. Счётчики сейчас в памяти одного процесса;
PM2 только fork, instances:1. Не запускать cluster/несколько реплик без общего
лимитера или согласованного лимитера на proxy; перезапуск сбрасывает счётчики.
TRUST_PROXY=none локально. За локальным Nginx — loopback, Node слушает
только 127.0.0.1; не доверять произвольным proxy адресам/заголовкам.

Helmet/CSP без unsafe-inline/unsafe-eval. Inline hero-script разрешён точным
SHA-256 хешем, рассчитанным из index.html при запуске; после изменения этого
HTML перезапустить Node. Существующий ранний запуск hero не переносился.
style-src-attr none; штатные анимации изменяют отдельные CSSOM свойства.
Статика только /site/css, /site/scripts, /site/img; остальные файлы/SCSS закрыты.
Семь публичных страниц через явные маршруты. Корень репозитория не раздаётся.
Приватные страницы и API проверяют роль независимо. /trainer.html публичный,
/trainer закрытый — разные адреса. Публичные страницы не создают сессии.
Старые HTML/SCSS/JS и компоненты не менялись; demo-ID и лимит99 не в БД.

Аудит: actor/target/action/requestId/time, без тел запросов, логинов неудачных
попыток, паролей, cookies, SID и CSRF. Восстановление CLI отмечается actor=null
как действие локального оператора. Критичные события в транзакции с изменением;

6. ПЕРЕД PRODUCTION / TLS-NGINX
Это НЕ выполненный деплой. Node24 поддерживается; перед production обновить
до актуального исправления безопасности ветки24 и повторить проверки.
Отдельные production DB/секреты, runtime роль без superuser и DDL; миграции
выполняет отдельный migrator. В локальной инструкции владелец БД и мигратор
совмещены ради простой подготовки dev/test, это не production-разделение.
NODE_ENV=production, APP_ORIGIN=https://реальный-домен, TRUST_PROXY=loopback
только при локальном Nginx. Node — loopback; PostgreSQL не открывать наружу.
Nginx не раздаёт корень IDEAL/закрытые HTML, проксирует закрытые маршруты Node.
Нужны реальная проверка Secure/__Host cookie, HSTS, Origin и forwarded headers
через TLS, no-store, отказ при сбое БД, HTTPS form без JS, рабочий graceful shutdown.
PM2 один fork процесс. Масштабирование потребует общего rate-limit хранилища.
Сессии/аудит чистятся только по согласованной retention; session prune каждые
~60 секунд с рандомизацией адаптера, абсолютный срок проверяется на чтении,
не зависит от своевременности prune. Audit retention пока не автоматизирован.
Backup/restore и эксплуатационные проверки следующих этапов не объявлены готовыми.
