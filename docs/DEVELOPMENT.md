## Доступ и безопасность

Роли OWNER / ADMIN / TRAINER взаимоисключающие. OWNER: `/admin`;
ADMIN: `/staff` → `/crm/clients`; TRAINER: `/trainer`.
Argon2id, серверные PostgreSQL-сессии, CSRF + строгий Origin, CSP, no-store,
rate limits, проверка authVersion и отзыв сессий должны сохраняться.
Каждую страницу/API защищать независимо. UI не является границей доступа. Расписание: OWNER/ADMIN — `/crm/schedule` и `/crm/visits`, TRAINER — `/trainer/lessons`; CRM- и trainer-POST-маршруты разделены по ролям.
Корень репозитория, `docs/`, исходники и секреты нельзя раздавать express.static.

## Интерфейс

HTML / EJS / SCSS / vanilla JS, BEM, без React. Основные формы и ссылки работают
без JavaScript. Уникальные стили — в SCSS соответствующей страницы, в патч
включать скомпилированный CSS. Без `!important`, `:root` и CSS custom properties.
Без маленьких тонких стрелок и стрелок в кружках. На тёмных кнопках светлый текст;
focus-visible, active scale(.98), reduced motion и мобильный адаптив обязательны.
Header/footer синхронизируются через `tools/sync_components.py`; Python для
просмотра через Go Live не нужен. Семь публичных страниц и их механики сохранять.
Демо-корзина/localStorage не являются источником CRM или реального магазина.

Остановить dev-сервер и worker (Ctrl+C), распаковать ZIP поверх IDEAL с заменой.
Проверить, что TEST_DATABASE_URL указывает на отдельную тестовую БД/пользователя.
В Windows CMD из `C:\Users\ШУМ\LITLE WORKS\IDEAL` выполнять по одной команде,
каждую следующую — только после успешного завершения предыдущей:

```bat
npm test
node tools/stage16-db-check.mjs snapshot > ..\ideal-before-stage16.json
npm run db:deploy
npm run db:generate
npm run db:status
node tools/stage16-db-check.mjs snapshot > ..\ideal-after-stage16.json
node tools/stage16-db-check.mjs compare ..\ideal-before-stage16.json ..\ideal-after-stage16.json
npm run dev
```

Если node_modules отсутствует, сначала `npm ci`. Если тесты или сравнение не прошли,
остановиться и разобрать ошибку; не использовать reset, db push или повторную установку БД.
Снимки не являются резервной копией. Инструмент только читает БД в repeatable-read
read-only транзакции, сохраняет количество строк и SHA-256 без содержимого строк.
Сравниваются все пользовательские public-таблицы, кроме `_prisma_migrations`;
в MembershipPlan исключаются два новых поля publicVisible/publicOrder, которых до
миграции нет. Для стабильного сравнения сервер/worker и любые другие записи в БД
должны оставаться остановлены между снимками. Совпадение доказывает только равенство
проверяемых данных между этими двумя снимками, не состояние будущих изменений.

После запуска: OWNER → Тарифы → Редактировать → публикация «Да» и нужный порядок.
На главной видны только активные опубликованные тарифы. Проверить обе категории,
отключение/скрытие, изменение цены, длинное название, пустые списки и мобильный вид.
Уже проданные абонементы сохраняют снимок цены/условий. Онлайн-продажа не добавлена.
Go Live показывает пояснение вместо актуального прайса — для данных нужен Express.

SEO пока выключено; домен отсутствует. Новые необязательные настройки описаны
в [SEO.md](SEO.md); включение индексации и деплой не входят в применение патча.

Проверить формы с JS и без него, клавиатуру/reduced motion, hero/Coverflow/drag,
каталог/товар/корзину/результат заказа, кабинеты по ролям, установочную плашку и offline.
Браузерные прогоны не заменяют проверку Safari/телефонов и системной доставки Push.
Результаты контейнера — [отчёт этапа 16](archive/STAGE16_INTEGRATION.md).
