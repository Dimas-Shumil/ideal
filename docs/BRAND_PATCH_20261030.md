# ИДЕАЛ — замена логотипа, 30.10.2026

## Что изменено

Официальный круглый знак восстановлен по приложенной фотографии 62×69 px с помощью imagegen. Это растровая реконструкция: точность до пикселя и исходная геометрия по настолько маленькому изображению не гарантируются. Оригинальный вектор не подменяется искусственным SVG. Серый круг остаётся частью знака; область за ним прозрачна. Один вариант подходит светлым и тёмным поверхностям.

Подготовлены PNG-master 1024, PNG/WebP 256 для интерфейса, favicon PNG 16/32 и ICO, PWA any 192/512, maskable 512, Apple 180 и OG 1200×630. В favicon используется только фирменный символ: текст в 16 px не читается. Maskable: полный круг занимает 76% стороны, укладывается в безопасный круг 80%. Большие иконки сохраняют надпись.

Обновлены статические страницы и общие компоненты; публичные EJS-шаблоны направлений, расписания, тренеров и магазина; вход, CRM, панели владельца/администратора/тренера; экран установки; метаданные и логотип HealthClub; иконка PUSH. Мобильное меню использует видимый логотип общего header. В hero и обычные пустые состояния лишние знаки не добавлены. В существующей брендированной заглушке фото тренера знак обновлён.

Новые URL изображений исключают повторное использование прежних иконок из HTTP-кеша. Старые PNG также обновлены для обратной совместимости. Файл общей стилизации имеет собственное имя brand-v1.css и исходник SCSS. Идентификатор manifest `/employee-app`, start_url `/`, scope `/`, URL SW и регистрация сохранены. SW не получает skipWaiting/clients.claim, не удаляет регистрацию и подписки, кеширование приватных данных не расширено. После выкладки завершить формы и закрыть все окна/вкладки приложения, затем открыть снова. ОС может обновлять установленную иконку с задержкой; удалять PWA и подписки для этого не требуется.

## Windows CMD — из корня существующего проекта

Сначала открыть терминал в нужном проекте. Выполнять блоки по очереди; при ошибке остановиться.

```bat
cd
git rev-parse --show-toplevel
git remote -v
git branch --show-current
git status --short --branch
```

Проверить: нужный IDEAL, ветка main, правильный origin. Если есть свои незакоммиченные файлы — сначала сохранить их отдельно или коммитом. Патч рассчитан на приложенный архив; не применять поверх другой несогласованной версии.

Сохранить ZIP в Downloads с именем IDEAL_LOGO_PATCH_20261030.zip. Затем, оставаясь в корне проекта:

```bat
powershell -NoProfile -Command "Expand-Archive -LiteralPath (Join-Path $env:USERPROFILE 'Downloads\IDEAL_LOGO_PATCH_20261030.zip') -DestinationPath (Get-Location).Path -Force"
node tools/check-brand.mjs
git diff --check
git diff --stat
git status --short
```

Проверить локально через существующий запуск:

```bat
npm run dev
```

Открыть главную, мобильный header/бургер, footer, вход, свои панели, /application; проверить отсутствие растяжения. Остановить dev через Ctrl+C. Если зависимости уже установлены, дополнительных npm ci / Prisma-команд для патча не нужно. При необходимости восстановления node_modules использовать существующий package-lock: `npm ci`, без обновления версий. База для проверки изображений не требуется.

```bat

git diff --cached --stat

git commit -m "feat: apply official IDEAL branding and PWA icons"

git status --short --branch
```

## Production ideal-abakan.ru

Входить тем же SSH-пользователем, под которым работает существующий PM2. Перейти в реальный корень установленного IDEAL (путь не содержится в архиве — его нельзя достоверно подставить). Сначала:

```sh
pwd
git remote -v
git status --short --branch
pm2 list
```

Чтобы увидеть рабочие каталоги без вывода переменных окружения:

```sh
pm2 jlist | node -e 'let s="";process.stdin.on("data",d=>s+=d);process.stdin.on("end",()=>{for(const p of JSON.parse(s))console.log(p.pm_id,p.name,p.pm2_env.pm_cwd)})'
```

Обновление из корня IDEAL, только после успешного push. Скрипт сначала проверяет main, чистый Git, upstream репозитория IDEAL и ровно один web-процесс PM2 из текущего каталога. Проверяет, что входящие изменения ограничены списком этого патча. Не выполняет reset, npm install, миграции, seed, сброс сессий или обновление окружения PM2. При неоднозначности завершится до merge/restart.

Новый deploy-brand.mjs ещё отсутствует на сервере до pull, поэтому первый pull выполняется отдельно:

```sh
(
set -eu
test "$(git branch --show-current)" = main
test -z "$(git status --porcelain)"
git fetch origin
git diff --name-only HEAD origin/main
)
```

Сверить вывод: только файлы из BRAND_PATCH_FILES.txt (список в ZIP/локальном проекте). Если есть package.json, lock, prisma, auth, .env или другие посторонние изменения — остановиться и разобрать отдельно. После проверки:

```sh
(
set -eu
test "$(git branch --show-current)" = main
test -z "$(git status --porcelain)"
git merge --ff-only origin/main
node tools/deploy-brand.mjs
node tools/check-brand.mjs https://ideal-abakan.ru
curl -fsS --max-time 15 https://ideal-abakan.ru/health/ready
curl -fsS --max-time 15 -o /dev/null https://ideal-abakan.ru/
git status --short --branch
)
```

Использован origin/main: перед fetch обязательно проверить его URL из git remote -v. Если production отслеживает другой remote, нельзя слепо менять remote — использовать уже проверенный upstream. Скрипт deploy-brand проверяет текущий upstream сам.

Патч не меняет .env, Prisma, PostgreSQL, аккаунты, роли, сессии, VAPID-ключи, подписки, SSH, Nginx, конфигурацию PM2 и другие сайты. Перезапускается только найденный web-процесс; возможен краткий перерыв ответа. systemd PUSH-worker не трогается. БД и uploads не включены в патч.
