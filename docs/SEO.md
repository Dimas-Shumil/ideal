# Публичный прайс и SEO — этап 16

## Публичные данные

Главная `/` выводит опубликованные активные тарифы CRM и товары серверного магазина.
Публичные тарифы выбираются по allowlist полей в `server/modules/public/plans.js`;
клиенты, платежи, сотрудники, версии и история CRM не отдаются в публичный HTML.
Управление прайсом: OWNER → Тарифы → Редактировать → «Показывать на сайте» и порядок.
Ни создание CRM-тарифа, ни сама миграция не публикуют его автоматически.
Изменённые данные видны после обновления страницы, не в реальном времени в открытой вкладке.

Главная остаётся no-store. JS не требуется для чтения тарифов: обе категории видны,
при включённом JS работают переключение, drag и клавиатура. Go Live — только превью
вёрстки: старых самостоятельных цен на главной больше нет. Публичное расписание подключается в этапе 17 отдельной безопасной выборкой.
Каталог и профили тренеров этапа 18 серверные, но пока остаются noindex; онлайн-записи и онлайн-продажи абонементов нет.

## Настройки

По умолчанию `SEO_ORIGIN` пустой, `SEO_INDEXABLE=false`: индексация запрещена,
robots.txt содержит Disallow: /, sitemap.xml — пустой валидный urlset без localhost.
При пустом SEO_ORIGIN абсолютные canonical/OG/JSON-LD не подставляются.
Новых секретов и обязательных настроек для локального запуска нет.

После выбора и подтверждения домена вручную задать в существующем .env:

- APP_ORIGIN — HTTPS origin выбранного домена;
- SEO_ORIGIN — тот же origin без пути, query и завершающего `/`;
- SEO_INDEXABLE=true — только после проверки контента и готовности публичных страниц;
- NODE_ENV=production — действующие production cookies/HTTPS/CSP сохраняются.

Не копировать примерный домен из тестов. В production несовпадение SEO_ORIGIN и
APP_ORIGIN, HTTP, localhost/IP или включение без домена останавливают запуск.
В development/test всегда noindex, даже при заполненных SEO-настройках.
Перед запуском реальной индексации — отдельная проверка на выбранном домене.

## URL и индексация

| URL | Поведение после включения SEO в production |
| --- | --- |
| `/` | Индексируемая главная, canonical `/` |
| `/index.html` | 301 на `/`, query сохраняется; браузер сохраняет fragment |
| `/shop.html` | Индексируемый каталог |
| `/shop.html` с параметрами | noindex,follow; canonical основного каталога |
| `/product.html?id=UUID` | Активный товар индексируется, canonical с этим id |
| `/product.html` без id | Страница выбора товара, noindex |
| Неизвестный/выключенный товар | HTTP 404, noindex |
| `/about.html`, `/trainers.html`, `/trainer.html` | noindex до получения и проверки реальных материалов |
| Главная с query | noindex,follow; canonical `/` |
| Корзина, заказ/результат, вход, кабинеты, API | noindex; прежние no-store и защита доступа сохранены |
| Неизвестная страница | HTTP 404, noindex |

Sitemap включает только `/`, `/shop.html` и активные товары. Нет сессионных URL,
фильтров, демо-профилей или выдуманных lastmod. Robots дополнительно закрывает
служебные пути. Robots/noindex не заменяют авторизацию и не являются защитой данных.
Все ответы получают X-Robots-Tag; готовые публичные страницы переопределяют его
согласованной политикой. Static preview HTML остаётся noindex.

## Метаданные

Title/description для главной, публичных информационных страниц и каталога;
название/описание товара — из серверного источника. Canonical и Open Graph берут
origin из конфигурации, а не Host запроса. Значения экранируются в HTML/EJS.
Минимальный JSON-LD WebSite на главной: только имя «ИДЕАЛ» и настроенный URL.
Его SHA-256 добавляется в CSP без unsafe-inline. Нет выдуманных отзывов, рейтингов,
биографий, достижений, телефонов и реквизитов. OG-картинка и расширенная разметка клуба
отложены до подтверждённых материалов. SEO не гарантирует позиции в поиске.

## Границы приёмки

Домен ещё не выбран; indexable=true проверялся через HTTP на тестовом домене,
без публикации и без обращения к поисковикам. Реальные материалы и юридические тексты
ожидаются. Работоспособность на реальном HTTPS/Nginx и индексация поисковыми системами
не подтверждены. Фактические проверки: [отчёт](archive/STAGE16_INTEGRATION.md).

## Публичные тренеры — этап 18

/trainers.html и /trainers/<public-key> — SSR, no-store, noindex,follow; canonical
при настроенном SEO_ORIGIN. В sitemap пока не добавляются. Имя в title экранируется,
автоматической Person-разметки с неподтверждёнными фактами нет. /trainer.html — 301

## Дополнение 29.10.2026 — домен ideal-abakan.ru, SEO/AEO/GEO и плавающие CTA

### Домен и индексация

Новый утверждённый origin: `https://ideal-abakan.ru` (без `www`, завершающего `/` и пути).
В `.env.example` задан `SEO_ORIGIN=https://ideal-abakan.ru`. **Реальный `.env` не перезаписывать**:
для локального запуска сохранить `NODE_ENV=development`, `APP_ORIGIN=http://127.0.0.1:3000`,
`SEO_INDEXABLE=false`, `SEO_CONTENT_INDEXABLE=false`; в разработке никакой localhost в sitemap/canonical не попадает.

Только после выпуска на HTTPS, проверки доступа и наполнения сайта публичными данными выставить
в серверном `.env`:

```env
NODE_ENV=production
APP_ORIGIN=https://ideal-abakan.ru
SEO_ORIGIN=https://ideal-abakan.ru
SEO_INDEXABLE=true
SEO_CONTENT_INDEXABLE=false
```

Когда реальные **публично одобренные** материалы «О клубе», направления, тренеры и расписание
наполнены и проверены, отдельно включить `SEO_CONTENT_INDEXABLE=true`. При этом даже с флагом
индексируются **только наполненные и опубликованные** информационные страницы без фильтров:
- О клубе: опубликованные title/summary/body;
- направление: опубликованные title/summary/body;
- тренеры: каталог с опубликованным профилем; профиль — при фото и описании;
- расписание: есть неотменённое опубликованное занятие текущей недели;
- магазин/товары: действующие правила публичной индексации из этапа 16.

`sitemap.xml` выводит только разрешённые опубликованные страницы; фильтры, приватные URL и черновики исключаются. `robots.txt` не блокирует `/trainers.html` ошибочным префиксом `/trainer`.

### Данные для AEO/GEO

На главной в JSON-LD — `WebSite`; тип `HealthClub` появляется **только** когда OWNER опубликовал действительные адрес и телефон в «Контент сайта → Контакты». Рядом публикуются существующие VK/Telegram, если они указаны, без вымышленных рейтингов, стоимости, часов, отзывов и координат. Контакты отображаются людям и роботам в обычном HTML; клик «Позвонить» использует актуальный E.164-номер.

Google не требует специального «AI-файла» или отдельной схемы для AI Overviews. Развивайте реальные ответы на вопросы (как записаться, где находится клуб, какие занятия доступны) **на публичных страницах**, только в соответствии с фактическими условиями.

### Плавающие кнопки

«Позвонить» (`tel:`) и «Записаться» (прокрутка к реальным контактам, **не** фиктивная онлайн-запись) появляются после прокрутки и скрываются у футера. Контролы не отображаются, пока OWNER не опубликует телефон в контактах. Работают на главной, магазине, каталоге, публичном расписании и страницах тренеров/направлений; в закрытых кабинетах не используются. JavaScript внешний (сохраняется CSP), стили находятся в `site/sass/main.scss` с готовыми `site/css/main.css` и `site/css/main.min.css`.

### После развёртывания

1. На HTTPS убедиться в одном основном домене: HTTP и `www` → 301 на `https://ideal-abakan.ru`, настроить SSL на сервере и `TRUST_PROXY=loopback` только при доверенном локальном reverse-proxy.
2. Проверить `/robots.txt`, `/sitemap.xml`, заголовки X-Robots-Tag, canonical, OG-карточки, и URL изображений; включить индексацию только после наполнения сайта и подтверждения контактных данных.
3. Подключить Яндекс Вебмастер (регион Абакан), Яндекс Бизнес и Google Search Console; отправить sitemap и пройти проверку информации об организации.
4. Проверить Lighthouse/PageSpeed на **боевом HTTPS-домене**, мобильных сетях и реальных страницах. Значения 100/100 и позиции в поиске невозможно гарантировать без измерений и контента.

Не путайте эту подготовку с выпуском сайта: DNS, SSL и реальная индексация не изменяются патчем в репозитории.
