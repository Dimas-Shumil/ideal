# PWA — этап 15

Согласовано 25 октября 2026. Приложение ориентировано на OWNER/ADMIN/TRAINER.
Публичный сайт доступен по прежним ссылкам. Клиентского кабинета нет.

## Запуск и установка

Manifest `/manifest.webmanifest`: id `/employee-app`, scope `/`, start_url `/login`,
standalone. Без сессии — вход; с действующей сессией — прежний серверный переход
по роли. Сессия, cookie и права остаются серверными. Установка не гарантирует
сохранения входа при истечении сессии. Установленное приложение не хранит данные offline.

Все три роли видят «Приложение» в общей навигации. `/application` защищён
requireAuth/requireRole, no-store. Кнопка установки показывается только при наличии
beforeinstallprompt, без принудительного диалога. На iPhone — инструкция через
«Поделиться» → «На экран Домой». Android/Chrome и Windows/Chrome, Edge приоритетны.
В установленном режиме кнопка скрывается. Поведение доступности установки зависит
от браузера; desktop viewport не заменяет тест реального телефона.
Метаданные и регистрация подключены к входу и EJS-кабинетам; публичное меню не менялось.

Иконки временные: существующее текстовое написание «ИДЕАЛ.» на тёмном фоне, без
новой эмблемы. PNG 192/512 (any), отдельная 512 maskable с безопасными полями,
Apple Touch 180. После получения логотипа заменить файлы и проверить safe zone.
Manifest не содержит shortcuts в закрытые данные или параметров пользователя.

## Один Service Worker и согласие Push

Сохраняется URL `/push-sw.js` и root scope `/`. Регистрация PWA не вызывает
Notification.requestPermission, subscribe, unsubscribe или восстановление подписки.
Включение/отключение Push остаётся на `/notifications` по явному действию.
Не удалять регистрацию SW при logout: это нарушило бы существующий Push lifecycle.
allowlist notificationclick сохраняется: /trainer/lessons, /crm/schedule,
/notifications, /shop-panel/orders. Query/hash удаляются, внешние URL отклоняются.

## Offline и сеть

Cache Storage `ideal-pwa-offline-v1` содержит ровно `/offline.html` и
`/site/css/pwa.css`. Это единственный allowlist. Установка SW получает их без
credentials, отказывается от редиректов, ошибочных ответов и Cache-Control: no-store.
Нет универсального cache-first для GET, HTML сессий, авторизации, API, магазина,
корзины, checkout, заказов, CSRF и персональных данных в кэше нет.

Только same-origin GET navigation идёт в сеть с fallback при сетевом исключении.
Обычные HTTP 401/403/404/500/503 возвращаются как есть, не подменяются offline-экраном.
POST/PUT/PATCH/DELETE и ненавигационные API-запросы не перехватываются. Очередей,
Background Sync и автоматического повторения операций после соединения нет.
При неудаче POST браузер может показать собственную ошибку сети. При неизвестном
результате операции сначала проверить актуальную запись/историю, затем решать о повторе.

Offline-экран не содержит пользователя и имеет явную ссылку открытия `/login`.
Он не открывает страницу автоматически при восстановлении сети. Обновление открытой
формы без сети не сохраняет введённое: приложение не обещает сохранность черновиков
после ручного закрытия/перезагрузки. На первом посещении без ранее установленного
SW offline fallback недоступен. При недоступности Node/сети экран не различает причины.

## Обновление

Нет skipWaiting, clients.claim, принудительной перезагрузки и массового unregister.
Новый SW остаётся waiting, пока открыты окна под прежним SW. На `/application`
отображается инструкция завершить работу, закрыть ВСЕ вкладки/окна сайта и
приложения, затем открыть снова. Обычного refresh недостаточно для активации.
Первый SW тоже не захватывает уже открытую страницу принудительно; управление
начинается со следующей навигации/открытия. Браузер может задерживать проверки обновления.

При activate удаляются только старые кэши с точным префиксом `ideal-pwa-offline-`.
Другие кэши origin не затрагиваются. При изменении offline.html или pwa.css
обязательно повышать CACHE_NAME в SW, чтобы изменился сам SW и создался новый кэш.
Обновление серверных страниц отдельно от SW не является атомарным релизом;
в этом этапе общие JS/CSS приложения не кэшируются SW.

## Применение

Распаковать ZIP-патч в корень IDEAL с заменой. Удалений нет. .env не менять.
Новых зависимостей, настроек и миграций нет. При существующих node_modules:

```bat
npm test
npm run dev
```

Если зависимостей нет, сначала `npm ci`. `npm test` использует только отдельную
TEST_DATABASE_URL и очищает тестовые данные. Не направлять её на рабочую БД.
Прежний полный набор 121 тест сохранён по количеству; один тест Push-роута обновлён
с прежнего запрета любого кэша на ограниченный PWA-сценарий. Добавлено 9 тестов PWA.

## Локальная приёмка

Проверить OWNER/ADMIN/TRAINER, отсутствие административного доступа у TRAINER,
выход/повторный запуск/истечение сессии, desktop/mobile и клавиатуру. При отключённом
JS кабинеты продолжают работать online, интерактивная установка/статус не работают.

На localhost Chromium: Application → Service Workers — одна регистрация /push-sw.js
со scope /. Cache Storage — только два обезличенных ресурса. Включить offline,
открыть кабинет/корзину: fallback без прежних данных. POST не повторяется при online.
Проверить no-store ответов и отсутствие сетевых ошибок JS в online-режиме.

Для обновления временно изменить комментарий SW на локальной копии, открыть две
вкладки с формами. Проверить waiting, отсутствие перезагрузки и сохранение ввода.
Закрыть обе вкладки и все окна приложения, открыть снова и проверить новый SW.
Удаляется только старый ideal-pwa-offline-*; чужой тестовый кэш должен сохраниться.
Вернуть временное изменение до Git-коммита.

Отдельно на реальных Android и iPhone: установка, значок, запуск, offline и согласие
Push. Не считать подключённую подписку подтверждением системной доставки.
Фактические проверки текущего патча — [отчёт](archive/PWA_STAGE15.md).
