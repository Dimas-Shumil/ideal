# Галерея тренера

В кабинете TRAINER появился раздел «Мои фотографии» (/trainer/gallery).
Каждый тренер управляет только галереей своего TrainerProfile, привязанного по userId.
Фамилии и позиции в каталоге не используются для определения доступа.
Если профиль ещё не создан, владелец/администратор готовит его в «Публичные тренеры» для нужного сотрудника.
OWNER/ADMIN не получают доступ к изменению новых галерей; управление основным портретом и текстами осталось прежним.

До 20 снимков на тренера; JPEG/PNG/WebP до 5 МБ и 20 мегапикселей, один файл за загрузку.
Автоповорот, сжатие в WebP, удаление метаданных, максимум 1600×1600 и 1 МБ на сохранённый снимок.
После загрузки можно добавить подпись (300 символов), изменить её и удалить снимок с подтверждением.
Новые снимки показываются первыми. Публикация автоматическая в опубликованном профиле.
Скрытие профиля/отключение сотрудника/смена роли закрывают публичные изображения.
На сайте — после достижений, 3 колонки на компьютере, 2 на телефоне; пустой блок скрыт.
Крупный просмотр: кнопки, стрелки клавиатуры, Escape, возврат фокуса стандартным dialog.
Без JavaScript ссылка открывает само изображение.

## Применение в Windows CMD

Из корня своей рабочей копии сначала выполнить:

    git status
    git remote -v
    git branch --show-current

Остановить локальный сервер Ctrl+C. Распаковать содержимое ZIP в корень проекта с заменой файлов.
Патч не содержит .env, .git, node_modules и пользовательских загрузок. Удалять файлы не нужно.
Зависимости не менялись. Сделать актуальную резервную копию БД обычным способом.
Существующий .env с DATABASE_URL оставить на месте.

    npx prisma validate
    npx prisma migrate status
    npx prisma migrate deploy
    npx prisma generate
    node --test tests/trainer-gallery.test.js
    npm run dev

До deploy команда migrate status покажет новую неприменённую миграцию — ожидаемо.
Миграция 20261117100000_trainer_gallery создаёт только таблицу TrainerGalleryPhoto и индекс.
Она не меняет существующие записи. Фотографии хранятся в БД и включаются в её резервную копию.
Не использовать migrate reset, db push или тестовое заполнение рабочей БД.

В другом окне CMD:

    curl.exe --max-time 10 http://127.0.0.1:3000/health/ready

Если в .env задан другой PORT, использовать его в адресе.
Войти под тренером, открыть «Мои фотографии», добавить снимок, подписать, проверить свой публичный профиль.
Войти под другим тренером — первая галерея должна быть недоступна для управления.
На телефоне открыть кабинет, при необходимости через меню «Ещё»; проверить загрузку и крупный просмотр.

## Проверки при подготовке

Prisma validate и generate выполнены без подключения к рабочей БД.
SQL миграции сопоставлен с prisma migrate diff между исходной и новой схемой.
Тесты новой галереи: изоляция чтения/изменения/удаления, роли, Origin/CSRF, обработка изображения,
лимит и повторная отправка, отключённая учётная запись, отозванная сессия, скрытый профиль, экранирование подписей.
Тесты используют подмену слоя БД; реальная миграция PostgreSQL здесь не выполнялась.
Дополнительно проверены существующие тесты прав тренера, профилей, PWA и синтаксис JS, компиляция SCSS.
В исходном архиве уже падает один тест public-ui-controls.test.js про фиксированный номер плавающей кнопки.
Это воспроизведено на исходной копии; несвязанный код не менялся.
Проверка настоящих учётных записей, реальной PostgreSQL и визуальная проверка в браузере/телефоне остаются в вашей среде.
